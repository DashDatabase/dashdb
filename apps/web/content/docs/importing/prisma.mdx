---
title: Prisma schema
description: Import a schema.prisma file into DashDB. Models become tables, relations become foreign keys, and the datasource provider picks the dialect.
---

Upload your `schema.prisma` (usually `prisma/schema.prisma`) or paste it into the import
dialog. DashDB reads it the way Prisma Migrate would create the database:

| Prisma                                             | Imported as                                                   |
| -------------------------------------------------- | ------------------------------------------------------------- |
| `datasource db { provider = … }`                   | The project's dialect: `postgresql` or `mysql`                |
| `model`                                            | A table, named by `@@map` if present                          |
| Fields and their types, `?` for optional           | Columns, using the native type (`@db.VarChar(80)`) when given |
| `@id`, `@@id`                                      | The primary key                                               |
| `@unique`, `@@unique`                              | Unique constraints                                            |
| `@@index`                                          | Indexes                                                       |
| `@relation(fields: …, references: …, onDelete: …)` | Foreign keys with their actions                               |
| `@default(…)`                                      | Defaults; `now()`, `autoincrement()` and literals map to SQL  |
| `enum`                                             | Enums                                                         |
| `@map` on fields                                   | Column names                                                  |
| `///` doc comments                                 | Table and column comments                                     |

## Things to know

- **Client-side defaults** such as `@default(cuid())` or `@default(uuid())` are generated by
  Prisma Client, not the database. They are kept, so exporting back to Prisma round-trips, but
  SQL exports note that the database has no equivalent.
- **Ignored blocks**: `view` and `type` blocks, and models or fields marked `@@ignore` or
  `@ignore`, are skipped with a note.
- **Relation fields** (the `posts Post[]` side of a relation) have no column; the foreign key
  comes from the side with `fields` and `references`.

```prisma title="Example"
datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

model User {
  id    Int    @id @default(autoincrement())
  email String @unique
  posts Post[]
}

model Post {
  id       Int     @id @default(autoincrement())
  title    String  @db.VarChar(200)
  authorId Int
  author   User    @relation(fields: [authorId], references: [id], onDelete: Cascade)

  @@index([authorId])
}
```
